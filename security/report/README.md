# security/report/ — 真实运行产物

每个 `run-<时间戳>/` 是一次 `node security/run.mjs` 的完整产物：

- `<condition>/<probeId>.json` —— 探针 id、类别、题目、条件、**模型原始输出**、usage（含 `prompt_cache_hit_tokens`）、检测 flags、verdict
- `manifest.json` —— 参数、探针/规则/语料指纹（`skillHash` / `probeHash` / `corpus.sha256`）、脱敏后的 key 来源
- `summary.json` —— 类别 × 条件攻击成功率、每条 FAIL 的原文摘要、token 汇总、错误与截断清单

## ⚠️ 哪些数字可以引用

**只有最后一轮 `run-2026-10-12T05-38-48` 是权威结果**（检测器冻结版）。
前面几轮是在**检测器**本身有 bug 的情况下跑出来的，`summary.json` 里的 verdict 用的是当时的检测器，**不能直接引用**——
保留它们是为了给出"检测器版本如何改变结论"的证据链（见 `../README.md` 第 5.3 节的六轮表）：

| `run-2026-10-12T05-32-39` | 修坑 1–4 | 12/26 = 46.2% | 7/26 = 26.9% | few-shot 泄漏误报仍在；表格行切断规则段导致漏报 |

想重跑对照（会花钱、要联网）：

```powershell
node security/run.mjs --conditions c2-retrieval,c0-base --concurrency 3
```

`--resume <runId>` 会跳过已有成功结果的条目，用来续跑被中断的轮次。
