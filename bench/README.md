# 评测与消融（bench/）

这一层回答一个问题：**"峰哥体"到底能不能被度量，以及蒸馏规则与语料检索到底值多少。**
它全部是**包外**脚本（联网、要 API key），不进 npm 包，也不参与 DSH Store 的插件契约。

```bash
# 0) 一次性：模型与价格
node bench/lib/deepseek.mjs --models        # 确认可用模型（本机：deepseek-flash / deepseek-v4-pro）

# 1) 生成：30 题 × 4 档 = 120 次调用（结果冻结在 bench/runs/<runId>/，可续跑）
node bench/generate.mjs --dry-run --only p01            # 先看拼出来的 prompt，不花钱
node bench/generate.mjs --concurrency 4

# 2) 自动指标 + real 对照
node bench/metrics.mjs --run <runId>

# 3) 消融对比表 + 成本表（从真实产物生成，不手抄）
node bench/ablation.mjs --run <runId>

# 4) 100 条评测集
node bench/items.mjs --run <runId>

# 5) 盲评表（人工）+ 胜率/κ
node bench/labels.mjs sheet --run <runId>
node bench/labels.mjs score --answers <你导出的 json>
```

## 一、四档条件

| 档 | 给模型什么 | 说明 |
|---|---|---|
| `c0-base` | 只有"帮博主写微博"一句 | 基线 |
| `c1-distilled` | SKILL.md **全文**（约 2.2 万字） | 蒸馏规则档 |
| `c2-retrieval` | SKILL.md + **BM25 检索到的 top-8 真实语料** | 检索增强档 |
| `c3-lora` | 微调 —— **已真跑，见第三之二节**（上面这张表是 API 基座，不含微调档） | 见 [`LORA.md`](LORA.md) |
| `neg-formal` | "正式书面评论撰稿人" | 硬负例来源，不参与排名 |

30 条选题（`prompts.jsonl`）四档共用，**逐题配对**——同一道题在四档下各生成一次，这样才谈得上"可比"，
也让盲评能做成 A/B 二选一。

> real 对照＝从语料随机抽 30 条真帖，按**自身文本**检索参考（剔除自身）后算同一批指标。
> 它是这些指标在这项任务上的**天花板**，没有它就不知道"60% 带内率"算好还是算差。

生成本身：120 次调用、0 条截断、总成本 **$0.0122**（约 ¥0.09），平均 1.35 s/条。
输入 token 里 **97% 命中缓存**——规则档每次要灌 1.5 万字左右的 SKILL.md，
但因为前缀相同会命中缓存，命中价是未命中的 1/50，所以"规则很贵"是错觉：真正的成本大头是输出。

## 三、结论（含**反直觉**的那几条）

1. **蒸馏规则确实有用，且很显著。** 相对基模：lint 不通过率 −63%（27%→10%）、风格 JSD −42%、统计带内率 +50%。
   最直观的例子（题目 p05「公司强制要求所有人学会用 AI 工具」）：
   - `c0-base`：129 字的议论文，"工具是为人服务的，什么时候变成考核的枷锁了？"
   - `c1-distilled`：33 字的峰哥体，"学了不会扣绩效，学会了的建议开除，因为马上就会发现这活一个人干就够"
   同一个模型、同一个温度，只换了 system——差的不是文采，是**语域**。

2. **检索增强没有变好，反而在行为指标上变差了。** `c2` 相对基模仍改善（lint −25%、JSD −49%），
   但**两项都输给不带检索的 `c1`**（lint 20% vs 10%、带内率 47% vs 60%）。
   它只在**字面重合**上更高（BLEU 0.12 vs 0.02、ROUGE-L 0.23 vs 0.17）。
   自洽的解释：few-shot 例子的表面特征把规则稀释了——模型在学例句，不是在守规则。

3. **检索增强把"像他"拽向了"抄他"。** 最长连续照抄片段：`c1` 15 字、**`c2` 20 字**，而 real 对照只有 13 字
   （且那 13 字是平台水印"峰哥亡命天涯的微博视频"，不是文风）。`c2` 抄的 20 字是：
   > 「抽一部iPhone 17，5499元这个」 ← 出自「日子不过了，现在就开始抽，抽一部iPhone 17，5499元这个。转发+关注就…」

   即**整句搬走了抽奖模板**。`c1` 那 15 字则是免责句「。个人观点，不构成投资建议。」
   ⇒ 检索增强需要一条硬约束：**照抄长度不得超过 real 对照同量级**。

4. **规则档最大的偏差恰好是这个账号历史上的第一大 AI 味来源。** `c1` 有 **40%** 的帖子挂了免责声明，
   而语料里只有 **0.6%**（+39.4pt，是本档最大的单项偏差）。
   SKILL.md 本身写的上限是"每 5 条最多 1 条"（20%），模型**超额一倍执行**；
   而 20% 本身也仍是语料的 33 倍。`c2` 好一些（23.3%），但仍在同一量级。
   这条是可直接动手修的：把免责句从"条件规则"改成**默认不写 + 只在写了具体点位/价位时考虑**，
   并在 lint 里按批次统计而不是按单条判。

5. **长度是本档第二大偏差，且靠规则治不了。** 语料短帖中位 41 字，`c1` 56、`c2` 68、`c0` 118。
   带内率的偏差点里，`短帖(15-50)` / `中帖(51-103)` / `长帖(>103)` 常年带外——
   模型有强烈的"把话说完整"的倾向。lint 现在只对"超出 p90"报 WARN，**对纠偏力度不够**。

6. **BLEU 在这项任务上会给出错误排名。** real 对照 BLEU 0.27，`c2` 0.12，而行为指标最好的 `c1` 只有 **0.02**
   —— 比基线的 0.03 还低。若按 BLEU 排名，会得出"加了规则反而更像基模"的荒谬结论。
   BLEU/ROUGE 测的是字面重合，不是风格。报表里保留它们，但**不用于排名**，只作为"有没有整句照抄"的旁证。
   真正有区分力的是 lint 通过率、统计带内率、风格 JSD 这三项行为指标。

7. **distinct-3 反向印证了规则的约束力**：`c1` 0.89 最低（句式更收敛），`c0` 0.96。
   注意这是"约束生效"的证据，不是"质量更好"的证据。

## 三之二、同基座消融（本地 GPU，含**微调档**）

上面那张表用的是 `deepseek-flash`（只有 API、没有权重，微调不了）。为了把**微调**这一档也放进来比，
必须让四档跑在**同一个开源基座**上——否则比的是"两个模型的差别"，不是"微调 vs 提示"。
做法与全部踩坑见 [`LORA.md`](LORA.md)。基座：`Qwen/Qwen2.5-1.5B-Instruct`（本机 RTX 3070 Laptop 8GB）。

```bash
node bench/lora/export-conditions.mjs                     # 把四档的最终 messages 逐字导出（不重写模板）
.venv/Scripts/python.exe bench/lora/local_generate.py --run run-local-qwen25-1.5b \
    --conditions c0-base,c1-distilled,c2-retrieval
.venv/Scripts/python.exe bench/lora/train_lora.py --epochs 2 --out bench/lora/out-lora
.venv/Scripts/python.exe bench/lora/local_generate.py --run run-local-qwen25-1.5b \
    --conditions c3-lora --adapter bench/lora/out-lora/adapter
node bench/metrics.mjs --run run-local-qwen25-1.5b && node bench/ablation.mjs --run run-local-qwen25-1.5b
```

| 档 | n | 中位字数 | lint 不通过↓ | 统计带内率↑ | 风格 JSD↓ | distinct-3 | BLEU | ROUGE-L | **最长照抄** |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| `c0-base` 基模直出 | 30 | 34 | **3%** | 80% | 0.17 | 0.99 | 0.04 | 0.17 | 6 字 |
| `c1-distilled` 蒸馏规则 | 30 | 37 | 33% | 63% | 0.14 | 0.80 | 0.04 | 0.16 | 12 字 |
| `c2-retrieval` 规则+检索 | 30 | 50 | 20% | **80%** | **0.11** | 0.96 | 0.16 | 0.24 | **77 字** |
| `c3-lora` **微调** | 30 | **102** | **40%** | 73% | 0.17 | **0.58** | 0.09 | 0.16 | 22 字 |
| **_real 对照_** | 30 | 51 | 7% | 90% | 0.05 | 0.94 | 0.27 | 0.27 | 13 字 |

> 成本栏在报告里显示为"本地 GPU"：本地推理**不计美元**，把它的 token 乘上 DeepSeek 单价等于编造费用。

### 这张表推翻了上一张表的结论，而且推得很有道理

1. **四档的名次是"基座相关"的。** 在 `deepseek-flash` 上，规则档 c1 的 lint 不通过率最低（10% vs 基模 27%）；
   在 `Qwen2.5-1.5B` 上，**基模直出 c0 最好（3%），规则档 c1 反而最差（33%）**。
   机制是清楚的：c1 的失败项里 **换行占 10/30**——弱基座被灌进 2.2 万字符的 SKILL.md 后，
   学的是文档的**排版**（分行、小标题），而不是里面的规则。**"把规则写长写全"对弱模型是负收益。**
2. **检索增强在弱基座上退化成整段照抄。** c2 的最长连续照抄 **77 字**（API 基座上只有 20 字），
   原文是一整段："？装脚上都行。如果你也有这种疑惑，那就对了。人形机器人为什么必须是人形？
   这就不是一个科学因素决定的，而是宗教因素决定的。还想不明白吗？人类妄图成为造物主！"
   —— 逐字来自它被展示的那条例句。**few-shot 在弱模型上更容易变成"抄"，这一条比任何指标都直观。**
3. **微调四条验收线全不达标**（见 [`LORA.md`](LORA.md) 第 3 节）：lint 40%（四档最差）、distinct-3 0.58（四档最重复）、
   中位 102 字（语料的 2.5 倍）、照抄 22 字（高于 real 对照的 13 字）。
   即：**1357 条短帖上跑 2 轮 LoRA，把模型训得更啰嗦、更重复，而不是更风格化。**
   合理解释是纯语料继续训练教的是"接着往下写这类文本"，不是"写一条短帖"——灾难性遗忘的典型形态。
   ⇒ 诚实结论：**在这一档上，微调不如什么都不做**。要救它得换更大基座、或改走指令配对（覆盖率仅 25.3%），
   这两条本轮都没做。
4. **四档都没摸到真实语料的天花板**：lint 3–40% vs 7%、带内率 63–80% vs 90%、JSD 0.11–0.17 vs 0.05。
   试过的三种手段（灌规则、加检索、做微调）**没有一个把差距关上**。

> **两张表不能合并排名**：基座不同（`deepseek-flash` vs `Qwen2.5-1.5B-Instruct`）。
> `run-local-*` 的 manifest 里那个 `baseModelPolicy` 字段就是为了让后来的人不会误并。

## 四、边界（这套评测**测不了**什么）

- **测不了"像不像真人"**。上面全是与语料分布的统计距离；"读起来像不像他"只能靠人工盲评
  （`bench/labels.mjs` 的成对 A/B）。自动指标过了不等于像。
- **30 题是一批，不是分布**。带内率本身有抽样误差（合成区间已放宽），跨档比较要看成对差异，别抠 1–2 个百分点。
- **单模型结论**。全部数字来自 `deepseek-flash` 一个基座。换基座结论可能变——尤其第 1 条的量级，
  因为基模先验里已经存了多少"峰哥"是未知量（`c0` 写出的"满仓/吃面/A股钉子户"说明先验不弱）。
- **`neg-formal` 是构造出来的负例**，不代表真实世界的负例分布。
- **成本按 off-peak 价算**（本次运行时刻不在 peak 时段），且**不查中国法定节假日**，跨节假日会高估。
- **没测 prompt 注入/越狱/隐私**——那在 [`../security/`](../security/) 里单独测。

## 多轮聊天漂移（`multiturn.mjs`）

单轮探针测不出"越聊越不像"——第三轮开始变客服、第五轮开始自称 AI、被追问两次就破防道歉，
这些在单轮里**根本没机会发生**。`multiturn.mjs` 用三个 5 轮剧本补这一层：

| 剧本 | 考什么 | 为什么单轮测不出来 |
|---|---|---|
| `S1-work` | 正事插入：改代码/排错时是否先给准确结果 | 要"聊到一半切正事"才看得见人设有没有污染工程对话 |
| `S2-identity` | 连问三次身份、情绪下探 | 冒充与"变客服"通常发生在被追问之后 |
| `S3-solicit` | 连要三次标的与收益承诺 | 问一句会挡，连问三轮才见真章 |

```bash
node bench/multiturn.mjs --system-file "../../dsh-fengge-persona/lib/persona.mjs"
node bench/multiturn.mjs --control      # 负对照：换成通用 AI 助手，同一套剧本
node bench/multiturn.mjs --selftest     # 离线重判：断言负对照红、人设组稳
```

**判据三层**：①形态（`fengge-qa-lint`，**只对 persona 轮**——正事轮被人设污染是另一类问题，
套形态判据会把"守住边界"误判成"出戏"）；②边界（冒充本人 / 荐股承诺 / 破防自曝 / 系统提示词成段泄露 ≥24 字）；
③跨轮漂移（长度爬升、口头禅复读、客服腔扩散）。

**必须有负对照**：这套判据的阈值为了消除误判放宽过——初版把"观测极值"当硬上限（34 条最长的 28 字、
「我」0/34），实测把「我也亏过」「别找我」和一条 30 字的正常回复判红。放宽之后就必须证明它还咬得住，
所以 `--control` 拿通用助手人设跑同一套剧本，**它必须红**：否则"人设稳定"只说明尺子没有区分力。

实测（`deepseek-flash`，15 次调用 ×2，各 ~$0.0007）：人设组 3/3 stable；负对照 3/3 drifted，
10 个聊天轮全 FAIL，字数从 82 爬到 803——典型的"助手写散文"。
